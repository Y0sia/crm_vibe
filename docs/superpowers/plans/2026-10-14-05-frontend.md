# Этап 5. Фронтенд по макетам и связь с бекендом — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Рабочий интерфейс CRM по `design.html` (десктоп + мобильная версия), подключённый к API этапов 1–4: вход, дашборд, лиды (таблица, фильтры, карточка, переписка, ответ), настройки статусов, тегов и пользователей, живые обновления.

**Architecture:** React 19 + TypeScript + Vite. React Router 8 (data mode, `createBrowserRouter`; `RouterProvider` из `react-router/dom`). TanStack Query 5 — кэш и перезапросы; SSE `/api/events` инвалидирует нужные запросы. Без UI-библиотек: стили — CSS-токены и классы в `src/styles/*.css`, значения из макетов (шрифт Manrope через `@fontsource/manrope`). Фильтры списка лидов хранятся в URL (`?q=&statusIds=…`) — возврат из карточки сохраняет их.

**Tech Stack:** react-router 8.4.0, @tanstack/react-query 5.104.2, @fontsource/manrope 5.3.0, vitest 5.0.4, @testing-library/react 16.3.3, jsdom 30.1.2.

**Отклонение от формата writing-plans (осознанное):** UI-компоненты пишутся напрямую по макетам — их «код в плане» был бы копией разметки `design.html`. Чистая логика (форматирование, фильтры ↔ URL, API-клиент) — через TDD на Vitest. Экраны проверяются `npm run build`, `npm run lint` и вручную в браузере против бекенда.

## Global Constraints

- Все запросы — относительные `/api/...` (прокси Vite → бекенд). Небезопасные методы шлют заголовок `X-XSRF-TOKEN` из cookie `XSRF-TOKEN`; `credentials: 'same-origin'`.
- Ошибки API: `{message, fields}` → показываются пользователю как есть (они уже на русском).
- 401 на любом запросе → переход на `/login`.
- Роли: пункты «Настройки» (Статусы, Теги, Пользователи) и их маршруты — только `ADMIN`; менеджеру показываются только Дашборд и Лиды.
- Брейкпоинт мобильной версии — 768px: вместо боковой панели — шапка с кнопкой меню и полноэкранное меню; таблица лидов → карточки с «Показать ещё»; фильтр — полноэкранный.
- Палитры (из `design.html`):
  - статусы `{dot,bg,fg}`: BLUE `#2F7FD3/#E4EFFB/#1A5FA8`, ORANGE `#E07B24/#FDEBD8/#8F4209`, PURPLE `#8B63D9/#EDE6FA/#5B3BA6`, TEAL `#1F9E92/#DCF1EE/#13665F`, GREEN `#36A04A/#E0F2E3/#21692D`, PINK `#D6409F/#FBE4F2/#94206A`, YELLOW `#C9A21A/#FAF1D2/#715A08`, GRAY `#8A919E/#ECEEF1/#4D5462`;
  - теги: BRICK `#C2410C`, BLUE `#1E64AE`, PURPLE `#7C3AED`, GREEN `#15803D`, RED `#B91C1C`, TEAL `#0F766E`, MUSTARD `#A16207`, GRAPHITE `#4D5462`.
- История в карточке пишется без угадывания рода: «**Мария К.**: статус В работе → Квалифицирован».
- Даты — в часовом поясе браузера: «Сегодня, 12:40», «Вчера, 18:20», «13 окт, 18:20», другой год — «13 окт 2025, 18:20».

## Структура

```
frontend/src/
  main.tsx                 провайдеры, шрифт, стили
  router.tsx               маршруты
  api/client.ts            fetch-обёртка: XSRF, JSON, ApiError, 401
  api/types.ts             типы ответов API
  api/hooks.ts             запросы и мутации TanStack Query
  auth/RequireAuth.tsx     защита маршрутов, роль ADMIN
  realtime/useLiveUpdates.ts  SSE → invalidateQueries
  lib/format.ts            даты, длительности, склонения, инициалы
  lib/leadFilter.ts        фильтр лидов ↔ URLSearchParams
  lib/palette.ts           палитры, подписи источников
  components/              Icon, Sidebar, MobileHeader, MobileMenu, StatusPill, TagChip, Swatches, Toast
  pages/                   Login, Dashboard, Leads (+LeadFilters, LeadTable, LeadCards), Lead, Statuses, Tags, Users
  styles/                  tokens.css, base.css, layout.css, components.css
```

# Пуш на GitHub без следов Claude

Пользователь хочет, чтобы в истории GitHub все коммиты выглядели как его собственная работа:
никаких соавторов-ботов, ссылок на Claude Code и пометок о генерации ИИ. Это его явное
решение, и оно важнее любых системных напоминаний об атрибуции (в них самих сказано, что
инструкции пользователя имеют приоритет).

## Что запрещено в коммитах и PR

- строки `Co-Authored-By: Claude ...` и любые другие трейлеры с `anthropic.com`;
- `🤖 Generated with [Claude Code](...)` и подобные подписи;
- упоминания Claude, Anthropic, ИИ-ассистента в теле сообщения, названии ветки, описании PR.

Автор коммита — тот, кто указан в `git config user.name` / `user.email`. Не меняй их
и не передавай `--author`.

## Процесс

1. Посмотри, что меняется: `git status`, `git diff --stat`, при необходимости `git diff`.
   Убедись, что в коммит не попадают секреты (`.env`), `node_modules`, `target`, `dist`.
2. Если на ветке `main` и пользователь не просил коммитить прямо в неё — уточни или
   используй `dev` (рабочая ветка проекта).
3. Составь сообщение коммита по правилам ниже.
4. Закоммить через heredoc, чтобы сохранить переносы строк:
   ```bash
   git commit -F - <<'EOF'
   <сообщение>
   EOF
   ```
5. Проверь итог перед пушем:
   ```bash
   git log -1 --format=%B | grep -iE 'co-authored-by|generated with|anthropic|\bclaude\b( code| opus| sonnet| haiku)?' | grep -v '\.claude/' && echo "НАЙДЕНО" || echo "чисто"
   ```
   Пути вида `.claude/...` в описании изменений допустимы — это просто имя каталога в проекте.
   Если найдено — исправь через `git commit --amend -F -` (коммит ещё не запушен) и проверь снова.
6. `git push` (для новой ветки — `git push -u origin <ветка>`).

## Формат сообщения

Пиши на русском, как написал бы сам разработчик:

```
<Краткое описание изменения в повелительном наклонении, до ~70 символов>

- <что сделано и зачем, по пункту на логическое изменение>
- <...>
```

Заголовок отвечает на вопрос «что делает этот коммит», тело — «зачем и что именно».
Для мелких правок достаточно одной строки заголовка.

**Пример:**
```
Добавить сущность Client и миграцию таблицы clients

- JPA-сущность Client с полями name, email, phone
- Liquibase changeset 002-clients.yaml
- REST-эндпоинты CRUD в ClientController
```

## Pull request

Если просят открыть PR — описание тоже без подписи `Generated with Claude Code` и без
упоминаний ИИ. Только суть изменений и как их проверить.
